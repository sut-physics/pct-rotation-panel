# pCT Rotation Panel

โปรแกรม GUI บนคอมพิวเตอร์ (Windows / Ubuntu) สำหรับสั่งมอเตอร์หมุนกล่อง A/B ของระบบ pCT ผ่าน Arduino Mega โดยไม่ต้องพิมพ์คำสั่งใน Serial Monitor

> ## ⚠️ คำเตือน
> เฟิร์มแวร์และโปรแกรมนี้ **ยังไม่ได้ทดสอบกับฮาร์ดแวร์จริง** (มอเตอร์, ALPIDE, TSS relay)
> ห้ามใช้ยิงลำแสงจริงก่อนตรวจสอบโค้ดและทดสอบทีละขั้นด้วยตัวเอง
> ข้อจำกัดสำคัญ: ระหว่างมอเตอร์หมุนหรือยิง เฟิร์มแวร์ไม่อ่าน Serial จึง **สั่งหยุดกลางทางไม่ได้** ให้เตรียมตัดไฟมอเตอร์ด้วยมือเสมอ
> มอเตอร์แรงไม่พอผ่านโซนแรงโน้มถ่วง (A 60–90°, B −60~−90°) ต้องช่วยดันด้วยมือ แล้วประกาศตำแหน่งจริงด้วย SETA/SETB

## โครงสร้างโปรเจกต์

```
pCT_RotationV2_Plan2_ManualFire.ino   เฟิร์มแวร์ต้นแบบเดิม (เก็บไว้อ้างอิง ไม่ใช้กับ GUI แบบเต็ม)
pCT_RotationV3_Protocol/              เฟิร์มแวร์ใหม่ที่คุยกับ GUI ด้วย protocol คงที่ (อัปโหลดตัวนี้ขึ้นบอร์ด)
gui/pct_panel.py                      โปรแกรม GUI (Tkinter + pyserial)
gui/commands.json                     ปุ่มและช่องกรอกทั้งหมดของ GUI
gui/config.json                       baud, ค่า home, โซนเตือน, timeout ฯลฯ
install.sh / run.sh                   ติดตั้ง / เปิดโปรแกรม บน Ubuntu
install.bat / run.bat                 ติดตั้ง / เปิดโปรแกรม บน Windows
```

## 1. ติดตั้งและเปิดโปรแกรม

### Ubuntu / Debian
```bash
git clone https://github.com/sut-physics/pct-rotation-panel.git
cd pct-rotation-panel
./install.sh      # ครั้งแรกครั้งเดียว
```
`install.sh` ทำ 2 อย่าง: ติดตั้ง `python3-tk` กับ `python3-serial` ด้วย apt และเพิ่มผู้ใช้เข้ากลุ่ม `dialout` (ต้องมีสิทธิ์นี้ถึงจะเปิด `/dev/ttyACM0` ได้)
**ถ้าสคริปต์บอกว่าเพิ่มเข้ากลุ่ม `dialout` ให้ logout แล้ว login ใหม่ 1 ครั้ง** ก่อนเปิดโปรแกรม

เปิดโปรแกรม:
```bash
./run.sh
```

### Windows
1. ติดตั้ง Python 3 จาก https://www.python.org/downloads/ ตอนติดตั้ง **ติ๊ก "Add python.exe to PATH"** และอย่าเอา "tcl/tk and IDLE" ออก
2. ดาวน์โหลดหรือ clone โปรเจกต์นี้ (ปุ่ม Code → Download ZIP แล้วแตกไฟล์)
3. ดับเบิลคลิก `install.bat` (ติดตั้ง pyserial) ครั้งแรกครั้งเดียว
4. ดับเบิลคลิก `run.bat` เพื่อเปิดโปรแกรม

Windows ไม่ต้องตั้งสิทธิ์พอร์ต พอร์ตจะขึ้นเป็น `COM3` หรือชื่ออื่น ถ้าบอร์ดไม่ขึ้นเลยให้ตรวจไดรเวอร์ (บอร์ดที่ใช้ชิป CH340 ต้องลงไดรเวอร์เอง)

### อัปโหลดเฟิร์มแวร์ขึ้น Arduino Mega (ทำก่อนใช้ GUI)
1. เปิด `pCT_RotationV3_Protocol/pCT_RotationV3_Protocol.ino` ใน Arduino IDE (ต้องเปิดจากโฟลเดอร์ที่ชื่อตรงกับไฟล์)
2. Tools → Board → **Arduino Mega or Mega 2560**, เลือกพอร์ต
3. กด Upload
4. **ปิด Serial Monitor ของ Arduino IDE ก่อนเปิด GUI** เปิดพอร์ตซ้อนกันไม่ได้

หรือใช้ arduino-cli: `arduino-cli compile --fqbn arduino:avr:mega pCT_RotationV3_Protocol` แล้ว `arduino-cli upload -p <พอร์ต> --fqbn arduino:avr:mega pCT_RotationV3_Protocol`

## 2. วิธีใช้โปรแกรม

1. เลือกพอร์ตจาก dropdown (ถ้าไม่เห็น เสียบสายแล้วกด **รีเฟรช**) กด **เชื่อมต่อ**
2. รอประมาณ 2.5 วินาที **บอร์ด Arduino จะรีเซ็ตทุกครั้งที่เปิดพอร์ต** ค่ามุมที่ GUI แสดงจึงกลับเป็นค่า home (A 37.1 / B −35.0) และสถานะ "ยังไม่ init"
3. ถ้าเครื่องอยู่ที่ตำแหน่งอื่น ให้ **ประกาศตำแหน่งจริงก่อน** ในบล็อก "คาลิเบรต / แก้ตำแหน่ง": ใส่ค่ามุมจริงที่วัดได้แล้วกด **ประกาศ A** และ **ประกาศ B** ให้ครบทั้งคู่ (ไม่ขยับมอเตอร์) หรือกด `start` เพื่อให้มอเตอร์ไปจุดสมมาตร
4. เมื่อสถานะเป็น "init แล้ว" จึงสั่งมุมได้

### บล็อกในหน้าจอ
| ส่วน | ใช้ทำอะไร |
|---|---|
| **ตำแหน่งปัจจุบัน** (ซ้าย) | แสดงมุม A/B ที่เฟิร์มแวร์รายงาน, สถานะ init, dwell, ว่าง/กำลังทำงาน มุมนี้เป็นค่าที่เฟิร์มแวร์นับเอง ไม่ได้อ่านจากเซนเซอร์ ถ้ามอเตอร์ไม่ถึงจริงหรือดันมือ ค่าจะไม่ตรงกับตำแหน่งจริง ต้องแก้ด้วย SETA/SETB |
| **ขยับมอเตอร์ (ไม่ยิง)** | `start` ไปจุดสมมาตร (A 90 / B −90), `close` กลับ home, ช่อง "A →" ไปมุมแบบซิงค์ (B = A − 180) พร้อมปุ่ม ±1/5/15 |
| **คาลิเบรต / แก้ตำแหน่ง** | `A<มุม>` / `B<มุม>` ขยับกล่องเดียว, `SETA` / `SETB` ประกาศตำแหน่งจริงโดยไม่ขยับมอเตอร์ |
| **พิมพ์คำสั่งเอง** | ส่งข้อความดิบไปที่เฟิร์มแวร์ เหมือน Serial Monitor (ใช้ลองคำสั่งใหม่) |
| **Serial log** (ขวา) | ข้อความจากเฟิร์มแวร์ทั้งหมด สีเขียว = สำเร็จ, สีแดง = ถูกปฏิเสธ |

### สิ่งที่ควรรู้
- ระหว่างมอเตอร์หมุน ปุ่มทั้งหมดจะถูกล็อกจนเฟิร์มแวร์ตอบ `#DONE` หรือ `#ERR` ถ้าค้างนานเกินไป (ค่าเริ่มต้น 240 วินาที) โปรแกรมปลดล็อกให้เอง หรือกด **ล้างสถานะ 'กำลังหมุน'**
- ตัวเลขที่ไม่ถูกต้องถูกบล็อกที่ GUI และเฟิร์มแวร์ก็ตอบ `#ERR bad_value` เหมือนกัน
- มุมที่เกิน 360° ต้องกดยืนยันก่อน (ปรับที่ `warn_abs_over` ใน `commands.json`)
- **เริ่มทดสอบจริงด้วยมุมเล็กๆ นอกโซนแรงโน้มถ่วงก่อนเสมอ**

## 3. วิธีแก้ logic (Arduino หรือ GUI)

หลักการ: GUI **ไม่เดา logic ของ Arduino** GUI อ่านเฉพาะบรรทัดที่ขึ้นต้น `#` ที่เฟิร์มแวร์ส่งมา ข้อความอื่นที่คนอ่านแก้ได้อิสระ ส่วนปุ่มและค่าตั้งอยู่ในไฟล์ JSON ที่แก้ได้โดยไม่ต้องแตะโค้ด Python

### 3.1 แก้เฟิร์มแวร์ (`pCT_RotationV3_Protocol.ino`)
- **ตัวรับคำสั่ง:** ฟังก์ชัน `handleCommand()` เป็นรายการ `if / else if` ของทุกคำสั่ง
- **กฎข้อเดียวที่ห้ามพลาด:** ทุกคำสั่งต้องจบด้วย `replyDone(F("ชื่อ"))` หรือ `replyErr(F("เหตุผล"))` ไม่งั้น GUI จะล็อกปุ่มรอจน timeout
- ถ้าคำสั่งเปลี่ยนตำแหน่งหรือสถานะ ให้เรียก `printState(true)` ก่อนเริ่มงานที่ใช้เวลานาน และ `printState(false)` หลังจบ ตัวนี้คือสิ่งที่ทำให้ตัวเลขใน GUI เปลี่ยน
- แก้ข้อความ `Serial.println(F("..."))` ที่ไม่ขึ้นต้น `#` ได้ตามใจ GUI แสดงใน log เฉยๆ
- ค่าคงที่ฮาร์ดแวร์ (พิน, สเปกมอเตอร์, ramp, `initAngleA/B`) อยู่ต้นไฟล์

**ตัวอย่าง: เพิ่มคำสั่ง `PARK` ที่พากล่อง A ไปมุม 0**
```cpp
else if (up == "PARK") {
  printState(true);
  moveSingleBoxA(0.0);
  printState(false);
  replyDone(F("PARK"));
}
```
แล้วเพิ่มปุ่มใน `gui/commands.json` (ดู 3.2) โดยไม่ต้องแก้ Python

### 3.2 แก้ปุ่มและช่องกรอก (`gui/commands.json`)
แก้ไฟล์แล้วกด **โหลด config ใหม่** ในโปรแกรม (ไม่ต้องปิดเปิดใหม่)

โครงสร้าง: `groups` แต่ละกลุ่มคือกล่องหนึ่งกล่อง มี `title` และรายการ `items`

| `type` | ใช้ทำอะไร | ค่าที่ตั้งได้ |
|---|---|---|
| `button` | ปุ่มส่งคำสั่งคงที่ | `label`, `send` |
| `row` | วางปุ่มหลายปุ่มในแถวเดียว | `items` (รายการ `button`) |
| `field` | ช่องกรอกตัวเลข + ปุ่มส่ง | ดูด้านล่าง |
| `note` | ข้อความอธิบาย | `text` |
| `separator` | เส้นคั่น | ไม่มี |

ตัวเลือกของ `field` และ `button`:

| ตัวเลือก | ความหมาย |
|---|---|
| `send` | ข้อความที่จะส่ง ถ้าเป็น `field` ใส่ `{value}` แทนค่าที่กรอก เช่น `"SETA{value}"` |
| `prefix`, `button`, `default` | ป้ายหน้าช่อง, ข้อความบนปุ่ม, ค่าเริ่มต้น |
| `busy` | `true` (ค่าเริ่มต้น) ล็อกปุ่มรอ `#DONE`/`#ERR`, ใส่ `false` ถ้าคำสั่งนั้นจบทันที |
| `requires_init` | `true` = GUI ไม่ยอมส่งถ้ายังไม่ init (เฟิร์มแวร์เช็กซ้ำอีกชั้น) |
| `warn_abs_over` | ถ้าค่าเกินตัวเลขนี้ ต้องกดยืนยันก่อนส่ง |
| `confirm` | ข้อความให้ยืนยันก่อนส่ง (ใช้กับคำสั่งอันตราย) |
| `nudge` | เพิ่มแถวปุ่ม ±ขั้น: `{"from": "A", "steps": [-5, 5]}` อ้างมุมจาก `#STATE` ของคีย์ `from` |
| `preview` | แสดงค่าที่จะสั่งอีกฝั่ง: `{"label": "B", "offset": -180}` |

**ตัวอย่างปุ่มของคำสั่ง `PARK` ที่เพิ่มด้านบน:**
```json
{ "type": "button", "label": "PARK → A 0", "send": "PARK" }
```

### 3.3 แก้ค่าตั้ง (`gui/config.json`)
| คีย์ | ความหมาย |
|---|---|
| `baud` | ต้องตรงกับ `Serial.begin()` ในเฟิร์มแวร์ (115200) |
| `boot_wait_ms` | เวลารอบอร์ดรีเซ็ตหลังเปิดพอร์ต |
| `busy_timeout_s` | ปลดล็อกปุ่มเองถ้านานเกินนี้ |
| `initial_state` | ค่าที่ GUI แสดงตอนเพิ่งต่อ ต้องตรงกับค่าเริ่มต้นในเฟิร์มแวร์ (`initAngleA/B`) |
| `state_display` | รายการมุมใหญ่ที่แสดง (`key` ตรงกับคีย์ใน `#STATE`, `zone` = ช่วงเตือนแรงโน้มถ่วง) |
| `state_extra` | รายการค่าย่อยที่แสดง (เช่น INIT, DWELL) เพิ่มคีย์ใหม่จาก `#STATE` ได้ที่นี่ |
| `protocol_prefix` | ตัวขึ้นต้นบรรทัดสถานะ (`#`) |
| `log_state_lines` | `true` = แสดงบรรทัด `#STATE` ใน log ด้วย (ใช้ debug) |
| `legacy_parsing` | `true` = อ่านข้อความไทย/อีโมจิของเฟิร์มแวร์ต้นแบบเดิมด้วย regex ใน `legacy_patterns` |
| `on_connect_send` | คำสั่งที่ส่งอัตโนมัติหลังต่อสำเร็จ (ว่างไว้ = ไม่ส่ง) |
| `show_raw_terminal` | ซ่อน/แสดงช่อง "พิมพ์คำสั่งเอง" |
| `dial` | วงกลมแสดงตำแหน่ง: `size` ขนาด px, `rotate` มุมบนจอ (ทวนเข็มจากขวา) ที่วาง 0°, `clockwise` มุมบวกหมุนตามเข็ม, `ticks` ระยะขีด |
| `sensor` | บอร์ดที่ 2 (เช่น ESP32 + BNO085 จาก `Angle_detection.ino`) ดูตารางด้านล่าง |

ตัวเลือกของ `sensor`:

| คีย์ | ความหมาย |
|---|---|
| `enabled` | `true` = แสดงแถวเชื่อมต่อเซนเซอร์ใต้แถวพอร์ตหลัก |
| `baud` | ต้องตรงกับ `Serial.begin()` ของบอร์ดเซนเซอร์ (9600) |
| `pattern` | regex ดึงตัวเลขมุมจากบรรทัด กลุ่มแรก `( )` คือค่ามุม บรรทัดที่ไม่ตรงจะแสดงใน log ทุกบรรทัด |
| `scale`, `offset` | มุมที่แสดง = ค่าที่อ่าน × `scale` + `offset` ใช้ปรับให้ตรงกับระบบมุมของ carriage |
| `compare_to`, `warn_diff` | เทียบกับมุมที่เฟิร์มแวร์นับ (คีย์ใน `#STATE`) ถ้าต่างเกิน `warn_diff` องศา ตัวเลขเป็นสีส้ม |
| `stale_ms` | ไม่มีค่าใหม่นานเกินนี้ ขึ้น "ไม่มีข้อมูลใหม่" และซ่อนจุด S บนวงกลม |
| `monitor_max_lines` | จำนวนบรรทัดสูงสุดในช่อง "Serial Monitor: เซนเซอร์" (กลางล่าง) เกินแล้วลบบรรทัดเก่าทิ้ง |
| `line_ending`, `buttons` | ส่งคำสั่งไปบอร์ดเซนเซอร์: ช่องพิมพ์ในกล่อง Serial Monitor เซนเซอร์ และปุ่มลัด `{"label", "send", "confirm"}` เช่น `z` = ตั้งศูนย์ |
| `zero_ref`, `zero_markers` | เมื่อเจอข้อความใน `zero_markers` (เช่น `Zero set!` หรือข้อความตอนบูตที่ตั้งศูนย์อัตโนมัติ) GUI จำมุมของ `zero_ref` (เช่น A) ตอนนั้นไว้ แล้วแสดงมุมเซนเซอร์ = ค่าที่อ่าน + มุมนั้น ใส่ `""` ถ้าไม่ต้องการ |

**ค่าที่ซ้ำกันสองที่ (ต้องแก้ให้ตรงกันเอง):** ค่า home และ dwell ใน `initial_state`, ช่วง `zone`, และ `info_text` อยู่ทั้งใน `.ino` และ `config.json` ถ้าแก้ที่เดียว ตัวเลขที่แสดงหลังต่อใหม่จะไม่ตรงกับเครื่อง จนกว่าเฟิร์มแวร์จะส่ง `#STATE` มาทับ (ส่งตอนบูตอยู่แล้ว)

### 3.4 แก้โค้ด GUI (`gui/pct_panel.py`)
ต้องแก้เฉพาะเมื่อเปลี่ยนหน้าตาหรือเพิ่มชนิด widget ใหม่:
- `parse_protocol()` / `parse_legacy()` แปลงบรรทัดจากเฟิร์มแวร์เป็นสถานะ (ไม่ผูกกับ GUI ทดสอบแยกได้)
- `build_item()` / `build_field()` สร้างปุ่มจาก `commands.json`
- `handle_line()` จัดการบรรทัดที่รับเข้ามา, `run_item()` ตรวจค่าและส่งคำสั่ง

## 4. Protocol (proto=1)

เฟิร์มแวร์ → GUI (ทุกบรรทัดจบด้วย `\n`)

| บรรทัด | ความหมาย |
|---|---|
| `#HELLO proto=1 fw=...` | ตอนบูต |
| `#STATE A=<deg> B=<deg> INIT=<0\|1> BUSY=<0\|1> DWELL=<ms>` | ตำแหน่ง/สถานะ ส่งตอนบูต, ก่อนเริ่มงานยาว, หลังจบงาน และทุก step ของ SCAN เพิ่ม `KEY=VALUE` ใหม่ได้ |
| `#DONE <cmd>` | คำสั่งสำเร็จ GUI ปลดล็อกปุ่ม |
| `#ERR <reason>` | คำสั่งถูกปฏิเสธ (`not_init`, `bad_value`, `unknown_cmd`, `scan_aborted`) GUI ปลดล็อกปุ่ม |

GUI → เฟิร์มแวร์: ข้อความบรรทัดเดียว `start`, `close`, `<มุม>`, `A<มุม>`, `B<มุม>`, `SETA<มุม>`, `SETB<มุม>`, `FIRE`, `SCAN<องศา/step>`, `X`, `D<ms>`, `K`, `?`

ตอนนี้ GUI มีปุ่มเฉพาะ ขยับมอเตอร์กับคาลิเบรต ส่วน `FIRE`, `SCAN`, `D`, `K` เฟิร์มแวร์รองรับอยู่แล้ว แต่ยังไม่มีปุ่มใน `commands.json` (เพิ่มเองได้ตามหัวข้อ 3.2 หรือส่งผ่านช่อง "พิมพ์คำสั่งเอง")

### เฟิร์มแวร์ V3 ต่างจากต้นแบบ V2 ตรงไหน
1. ค่าที่ไม่ใช่ตัวเลขตอบ `#ERR bad_value` (ต้นแบบอ่านเป็น 0 แล้วหมุนไป 0°)
2. `INIT=1` ต้องรู้ตำแหน่งครบทั้ง A และ B (ต้นแบบ SETA/SETB ตัวเดียวก็ปลดล็อก)
3. ระหว่าง SCAN รับทั้ง `X` และ `K` (ต้นแบบทิ้ง `K`)

ข้อจำกัดที่ยังเหมือนต้นแบบ: ระหว่างหมุน/ยิง (`delay`) ไม่อ่าน Serial

## ใช้กับเฟิร์มแวร์ต้นแบบเดิม (V2)
ตั้ง `legacy_parsing: true` ใน `config.json` (เป็นค่าเริ่มต้นอยู่แล้ว) GUI จะอ่านข้อความไทย/อีโมจิของต้นแบบด้วย regex ใน `legacy_patterns` แต่เปราะกว่า protocol ถ้าข้อความในเฟิร์มแวร์เปลี่ยน ตัวเลขใน GUI อาจไม่อัปเดต
